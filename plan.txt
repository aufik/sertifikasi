## 🛠️ Enterprise Architecture & Technical Specifications

### 1. STACK & ENVIRONMENT SPECIFICATIONS
- **Framework:** Laravel 12
- **Language:** PHP 8.3+ (Strict Types `declare(strict_types=1);` mandatory across all classes)
- **Database:** PostgreSQL (ULIDs for primary keys, JSONB for metadata, GIN for Full-Text Search)
- **Cache & Queue:** Redis
- **Architecture Pattern:** Layered Clean Architecture (Controller -> DTO/FormRequest -> Service -> Repository -> Model)

---

### 2. DIRECTORY STRUCTURE
Ensure the codebase strictly follows this enterprise organization:

```
app/
├── Actions/                  # Single-purpose domain actions
├── Contracts/
│   ├── Repositories/        # Domain repository interfaces
│   └── Services/            # Business service interfaces
├── DTO/                     # Data Transfer Objects (readonly properties)
├── Enums/                   # String-backed PHP Enums
├── Exceptions/              # Domain-specific custom exceptions
├── Helpers/                 # Global/Domain helper utilities
├── Http/
│   ├── Controllers/
│   │   └── Api/
│   │       └── V1/          # Versioned thin API controllers
│   ├── Middleware/          # Request trace, Auth, Rate Limiting
│   ├── Requests/            # Form request validation classes
│   └── Resources/           # API JSON serialization resources
├── Logging/                 # Custom log formatters/processors
├── Models/                  # Eloquent entities
├── Observers/               # Model lifecycle hooks / event triggers
├── Policies/                # Authorization policies (RBAC)
├── Providers/               # Custom service providers
├── Repositories/
│   └── Eloquent/            # Eloquent implementations of repository contracts
├── Services/                # Business logic services (transactions, domain logic)
├── Support/                 # Common utilities
└── Traits/                  # Reusable traits (e.g. ApiResponser)
```

---

### 3. CODING & DESIGN STANDARDS

1. **Clean Code & SOLID:** Strictly enforce Single Responsibility, Interface Segregation, and Dependency Injection.
2. **Thin Controllers:** Controllers MUST NOT contain business logic or raw DB queries. They only handle HTTP request mapping, delegate to Services, and return API Resources.
3. **Service Layer Boundaries:** All business logic, DB transactions (`DB::transaction`), and concurrency locking MUST reside within Services.
4. **Repository Abstraction:** Data persistence and complex PostgreSQL queries MUST be encapsulated inside Repositories via Interfaces.
5. **Strict Type Safety:**
   - Every file MUST begin with `declare(strict_types=1);`.
   - Constructor Property Promotion and `readonly` properties for DTOs.
   - Explicit return types for ALL functions/methods.
6. **Class & Method Limits:** Max 30 lines per method, max 300 lines per class.
7. **Traceability:** Automatic context propagation using `Log::shareContext(['request_id' => $requestId])`.

---

### 4. MANDATORY SYSTEM COMPONENT SPECIFICATIONS

#### 4.1 Unique Request Traceability Middleware (`AssignRequestId`)
- Generates a UUID v4 `X-Request-ID` if not provided in request headers.
- Shares the `request_id` globally with Laravel's logger via `Log::shareContext(['request_id' => $requestId])`.
- Attaches `X-Request-ID` to response headers.

#### 4.2 Standardized API Response Layer (`ApiResponser` Trait)
Unified JSON structures for all API responses.

**Success Response:**
```json
{
  "meta": {
    "success": true,
    "code": 20000,
    "message": "Operation successful",
    "request_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
    "timestamp": "2026-07-30T14:30:00+07:00"
  },
  "data": {}
}
```

**Paginated Response:**
```json
{
  "meta": {
    "success": true,
    "code": 20000,
    "message": "Operation successful",
    "request_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
    "timestamp": "2026-07-30T14:30:00+07:00",
    "pagination": {
      "current_page": 1,
      "per_page": 10,
      "last_page": 5,
      "total": 50,
      "has_more": true
    }
  },
  "data": []
}
```

**Error Response:**
```json
{
  "meta": {
    "success": false,
    "code": 40001,
    "message": "Validation Error",
    "request_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
    "timestamp": "2026-07-30T14:30:00+07:00"
  },
  "errors": {
    "sku": ["The SKU format is invalid."]
  }
}
```

#### 4.3 Global Exception Handler
- Intercepts `ValidationException`, `ModelNotFoundException`, `AuthenticationException`, `AuthorizationException`, and custom `ApiException`.
- Never spills HTML debug error pages in API environment.
- Returns standardized JSON error responses with custom domain error codes.

#### 4.4 Base Contracts & Classes
- `BaseController`: Uses `ApiResponser`.
- `BaseRepositoryInterface` & `EloquentBaseRepository`: Generic repository contracts and Eloquent driver abstraction.
- `BaseServiceInterface` & `BaseService`: Generic service interfaces and base error propagation.
- `ApiException`: Custom domain exception class supporting custom internal error codes and HTTP statuses.

#### 4.5 Security, Rate Limiting & Auth Strategy
- **Authentication:** Laravel Sanctum token-based authentication.
- **Authorization:** Granular Policy checking (`ProductPolicy` for view, create, update, delete, purge).
- **Throttling:** Custom rate limiters configured in `AppServiceProvider` / `routes/api.php` (e.g. 60 req/min for general API, 10 req/min for mutation endpoints).

#### 4.6 Concurrency & Race Condition Control
- Implement pessimistic locking (`lockForUpdate()`) in `ProductService` for critical inventory / status updates to prevent race conditions in multi-threaded requests.

#### 4.7 Database Seeder & Factory Strategy
- Provide `ProductFactory` with realistic fake data generators.
- Create `ProductSeeder` generating 10,000+ records to validate PostgreSQL B-Tree and Full-Text GIN index performance during testing.

#### 4.8 Quality & Dev Tools Configuration
- `pint.json`: Configured for PSR-12 & Laravel strict standards.
- `phpstan.neon`: Larastan level 8 zero-bleed strict type checking.
- `.editorconfig`: Standardized line endings, indentation, and trailing space rules.
- Custom logging channel `product_log` directing events to `storage/logs/product.log`.
