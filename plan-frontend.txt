## 🎯 Frontend Objective
Build a professional, maintainable, and production-ready admin frontend for the **Product Management Service** using:

- **Laravel 12** as the full-stack application shell
- **Inertia.js** as the server-driven SPA bridge
- **React 19+** for UI components
- **TypeScript** for type safety
- **Tailwind CSS** for styling
- **Vite** for frontend bundling

The frontend must integrate cleanly with the existing backend architecture while keeping UI logic, page state, API interaction, and component structure organized and scalable.

> Important: This document is a frontend implementation plan only. Do not execute implementation until explicitly instructed.

# 🧱 Recommended Frontend Architecture Principles

## 1. Pages Should Be Thin
Inertia pages should coordinate data and layout only. Complex UI should be extracted into partials/components.

Bad:
```tsx
// Huge Products/Index.tsx with table, filters, dialogs, and form logic all inline.
```

Good:
```tsx
<ProductsIndexPage>
  <ProductFilters />
  <ProductTable />
  <Pagination />
</ProductsIndexPage>
```

---

## 2. Keep UI Components Reusable but Not Over-Abstracted
Create reusable primitives for common elements, but do not over-engineer components before repeated usage exists.

Recommended reusable components:
- `Button`
- `Input`
- `Select`
- `Textarea`
- `DataTable`
- `Pagination`
- `StatusBadge`
- `ConfirmDialog`
- `PageHeader`

---

## 3. Server-Driven Pages, Not Client-Side API Duplication
Because this stack uses Inertia, prefer returning page props from Laravel controllers instead of duplicating all page fetches with client-side `fetch` or Axios.

Use client-side requests only for:
- Small async interactions
- Autocomplete
- Background refresh
- Future real-time features

---

## 4. URL Is the Source of Truth for List Filters
For product lists, search/filter/sort/pagination state should live in the query string.

Example:
```txt
/products?search=laptop&status=active&page=2&per_page=15
```

Benefits:
- Shareable URLs
- Browser back/forward works correctly
- Filters persist after refresh

---

## 5. Strong Type Alignment With Backend Resources
Frontend TypeScript types must follow backend API/Inertia resource output, especially:
- `ProductResource`
- `CategoryResource`
- Pagination metadata
- Authenticated user props
- Flash messages
- Validation errors
